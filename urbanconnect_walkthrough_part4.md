## Section A: Architecture & System Design

---

### Q1: What is UrbanConnect and how does it fit into the UrbanFlow platform?

**A**: UrbanConnect is a real-time community discussion module — think city-specific Reddit/Twitter. Citizens post about civic issues, vote, comment in threads, and tag local authorities. It integrates into UrbanFlow as a tab in the React Native app. What makes it unique is:
1. **AI-powered analysis** — every post is analyzed for sentiment, urgency, and misinformation
2. **Civic syndication** — reports from CivicConnect (another UrbanFlow feature) are automatically bridged into UrbanConnect
3. **City Pulse** — daily social media scraping + AI analysis to gauge public sentiment

---

### Q2: Explain the overall architecture. How many servers are involved?

**A**: Three main processes:

| Server | Role |
|---|---|
| **Node.js/Express** | REST API, MongoDB access, Redis caching, business logic |
| **Python AI Server** | LLM-powered analysis (sentiment, clustering, misinformation) |
| **Background Workers** | `node-cron` for daily City Pulse scraping and analysis |

Plus external services: MongoDB Atlas, Redis, Cloudinary, Apify, Tavily, Auth0.

The key architectural insight is the **fire-and-forget pattern** between Node.js and Python — the Express server sends posts to the Python server asynchronously after responding to the client, so users never wait for AI processing.

---

### Q3: Draw the request lifecycle for creating a post.

**A**: (See the detailed 12-step lifecycle in Part 2, Section 7, and the sequence diagram in Part 3, Section 13.)

Quick version:
1. Client uploads image to Cloudinary → gets URL
2. Client sends POST /ask with post data
3. Server: find/create user → create Question → invalidate Redis → respond 201
4. Fire-and-forget: send to Python /analyze-post → get AI results → update Question
5. Python calls /cluster-check → server checks cosine similarity → assigns clusterId
6. Next feed refresh shows AI badges

---

### Q4: Why separate the AI server from the Express server?

**A**: Three reasons:
1. **Language ecosystem**: Python has superior ML/AI libraries (LangChain, transformers, etc.)
2. **Resource isolation**: LLM inference is CPU/GPU intensive — decoupling prevents it from blocking HTTP requests
3. **Independent scaling**: AI processing can be scaled horizontally (more Python workers) without touching the main API

## Section B: Database & Schema Design

---

### Q5: Why is the main model called "Question" instead of "Post"?

**A**: Legacy naming. The feature originally started as a Q&A platform (like Stack Overflow), then evolved into a community discussion board. The `Question` name was kept to avoid breaking changes across the codebase.

---

### Q6: Explain the denormalization trade-offs in the Question model.

**A**: The `votes` field on `Question` is denormalized (also stored individually in `QuestionVote`). Trade-offs:

| Pro | Con |
|---|---|
| Feed queries are O(1) for vote display | Must maintain consistency with `$inc` |
| No aggregation needed per post | If `$inc` fails, count drifts from truth |
| Redis caching works better with pre-computed data | Two writes per vote (Vote doc + Question.$inc) |

Same pattern on `Comment.votes` and `Comment.replyCount`.

---

### Q7: How does the threaded comment system work? What's the schema design?

**A**: Self-referential `parentId` pattern in `commentModel.js`:
- Top-level comment: `parentId = null`
- Reply to a comment: `parentId = <parent comment's _id>`

Compound index: `{ questionId: 1, parentId: 1, _id: -1 }`

**Client implementation**: `CommentItem.jsx` is a **recursive React component**:
```jsx
<CommentItem comment={reply} depth={depth + 1} />
```
`depth` controls indentation and avatar sizing.

**Alternative considered**: Materialized path (`path: "/root/child1/child2"`) — this is faster for deep trees but harder to maintain.

---

### Q8: What is the `embedding` field on the Question model?

**A**: A 768-dimensional vector embedding generated by the Python AI server. It captures the semantic meaning of the post's content. Used for:
1. **Clustering**: Cosine similarity between embeddings to group similar posts
2. **RAG search**: (on announcements) vector search to find semantically related content

Storage: stored directly on the Question document as `[Number]`.

---

### Q9: How does the unique sparse index on `voteModel.js` prevent double-voting?

**A**: 
```javascript
voteSchema.index({ userId: 1, commentId: 1 }, { unique: true, sparse: true });
```

- `unique: true` → MongoDB rejects inserting a second document with the same (userId, commentId) pair
- `sparse: true` → The index only includes documents where both fields exist. Without sparse, if either field is `null` (e.g., when voting on a question, `commentId` is not set), all nulls would conflict with each other

---

### Q10: What is a TTL index and where is it used?

**A**: TTL (Time-To-Live) indexes automatically delete documents after a set duration. In `announcementModel.js`:

```javascript
announcementSchema.index({ expiresAt: 1 }, { expireAfterSeconds: 0 });
```

MongoDB's background thread checks every 60 seconds and deletes documents whose `expiresAt` is in the past. `expireAfterSeconds: 0` means "use the field's value directly as the expiry time."

## Section C: API Design & Server Logic

---

### Q11: Explain cursor-based vs. offset-based pagination.

**A**:

| Offset-based (`skip/limit`) | Cursor-based (`_id < cursor`) |
|---|---|
| `skip(100).limit(10)` | `find({ _id: { $lt: lastId } }).limit(10)` |
| Must scan + discard skipped docs | `_id` index seek — O(log n) |
| Page 1000 scans 10,000 docs | Page 1000 scans 10 docs |
| Insertion causes page drift | Stable across insertions |

UrbanConnect uses cursor-based pagination via the `after` query parameter. The client sends the last `_id` from the current page, and the server fetches the next batch.

---

### Q12: How does Redis caching work in the feed?

**A**: Cache key format: `urbanconnect:questions:after_{cursor}:limit_{limit}:user_{email}`

- **Cache hit**: Return cached JSON directly (60s TTL)
- **Cache miss**: Query MongoDB, compute response, store in Redis
- **Invalidation**: On every write (create, vote, comment), all keys matching `urbanconnect:questions:*` are deleted

**Key insight**: Per-user cache keys because the response includes `userVote` data that varies by user.

---

### Q13: What happens when a CivicConnect report is syndicated?

**A**: The `civicSyndication.js` service:
1. Checks if `reportStatus !== 'UNCERTAIN'` (guard)
2. Checks for duplicates via `Question.exists({ reportId })`
3. Maps the reporter's email to a UrbanConnect `User` (falls back to dummy ObjectId)
4. Creates a `Question` with `isCivicReport: true`, `reportId`, `reportCategory`
5. Invalidates Redis and sends to Python `/analyze-civic` endpoint
6. Updates the Question with AI results

The reverse direction is `patchQuestionVote` — when an UrbanConnect user upvotes a syndicated post, the vote is proxied back to CivicConnect's API.

---

### Q14: What is the clustering algorithm and how does it work?

**A**: File: `cluster.controller.js`. Pipeline:

1. Receive the new post's 768-dim embedding
2. Query all posts from the last 12 hours with embeddings
3. Compute **cosine similarity** between the new embedding and every recent post's embedding
4. Filter posts with similarity ≥ 0.75
5. If ≥ 2 similar posts found:
   - If any already has a `clusterId` → reuse it
   - Otherwise → generate `cluster_` + UUID
   - Tag all unclustered similar posts
   - If cluster reaches 3+ posts → generate AI headline and summary

**Why cosine similarity?** It measures directional similarity between vectors, ignoring magnitude — ideal for text embeddings where the angle, not the length, captures semantic meaning.

---

### Q15: Explain the hybrid search for announcements.

**A**: File: `announcement.controller.js`, function `searchAnnouncementsForRAG`.

Uses MongoDB Atlas Search with a `$search` aggregation stage:

```javascript
{
  compound: {
    should: [
      { knnBeta: { vector: embedding, path: "embedding", k: 5 } },  // Vector search
      { text: { query: queryText, path: ["title", "body", "department"] } }  // BM25 text search
    ],
    filter: [
      { equals: { path: "city", value: city } }  // City filter
    ]
  }
}
```

- **Vector component**: Finds semantically similar announcements using the embedding
- **BM25 component**: Finds keyword matches (handles exact terms the vector might miss)
- **Result fusion**: MongoDB computes Reciprocal Rank Fusion to merge both rankings

This powers the AI agent's RAG pipeline — when checking for misinformation, the AI retrieves relevant official announcements to fact-check against.

---

### Q16: What is the City Pulse pipeline?

**A**: File: `cityPulse.controller.js`. Runs daily at 2 AM via cron.

1. Scrape 4 sources in parallel: Tavily (15), Twitter/Apify (50), Reddit/Apify (20), News/Apify (10)
2. Normalize to `{ source, text, url }` format
3. Fetch yesterday's analysis for trend comparison
4. Send everything to Python `/analyze-pulse`
5. Save results as `SocialPulse` document

The AI produces: executive summary, sentiment metrics, trend analysis, extracted issues, recommended actions.

## Section D: Client-Side / React Native

---

### Q17: How does navigation work in the UrbanConnect tab?

**A**: Expo Router's nested Stack navigator:
- `_layout.jsx` defines the Stack with 3 screens: `index`, `create` (modal), `post/[id]` (dynamic)
- The `index` screen internally manages 4 "tabs" with `useState` — Feed, Explore, Profile, Announcements
- Tab switching is simple conditional rendering, not a nested Tab Navigator

---

### Q18: What is optimistic UI and where is it used?

**A**: Optimistic UI means updating the interface **immediately** before the server confirms success.

**Where used**:
1. **PostCard.jsx** — Like/unlike: toggle heart color and increment count instantly. If API fails, revert.
2. **CommentItem.jsx** — Voting: change vote display immediately. If API fails, revert.
3. **CommentItem.jsx** — Replying: append comment to state immediately. If API fails, remove it.
4. **CommentItem.jsx** — Saving: toggle bookmark icon immediately.

**Pattern**:
```javascript
// Optimistic: update state immediately
setLiked(true);
setLikesCount(prev => prev + 1);

// Fire API call
try {
  await api.patch('/questionVotes', { ... });
} catch (error) {
  // Rollback on failure
  setLiked(false);
  setLikesCount(prev => prev - 1);
}
```

---

### Q19: How does infinite scrolling work in the feed?

**A**: `FeedTab.jsx` uses React Native `FlatList` with:
- `onEndReached` callback → fires when user scrolls within 80% of the bottom
- `onEndReachedThreshold={0.8}` → triggers early for smoother experience
- Tracks `nextCursor` (last post's `_id`) and `hasMore` flag
- Guard: won't fetch if already `loadingMore` or `!hasMore`

---

### Q20: How does the CommentItem handle nested replies?

**A**: **Recursive rendering**. Each `CommentItem` receives a `depth` prop. When "Show replies" is tapped, it fetches replies from `/api/urbanconnect/replies?parentId=X` and renders each reply as another `<CommentItem depth={depth+1} />`.

Visual effects of depth:
- `marginLeft: depth * 16` (indentation)
- Avatar shrinks from 40px to 32px at depth > 0
- Border line on the left for replies

---

### Q21: How does the authority tagging feature work on the create screen?

**A**: `create.jsx` implements a two-step modal flow:
1. User types a city name → 500ms debounce → `GET /authorities/{city}`
2. Server returns matching officials from `Administration` collection
3. User toggles selection (checkmark + blue border)
4. Selected authority `_id`s are sent as `taggedAuthorities` in the POST /ask request
5. Server stores them as references on the `Question` document
6. Feed displays them as blue chips via `.populate('taggedAuthorities')`

## Section E: Security & Performance

---

### Q22: How is authentication handled?

**A**: Auth0 integration via `useAuthStore` (Zustand). The client passes user info (email, name, avatar) with each request. The server:
- Looks up / auto-creates users by email
- User identity is stored in the `User` collection
- No JWT validation on most endpoints (simplified for demo) — in production, middleware would verify Auth0 tokens

---

### Q23: What happens if the Python AI server goes down?

**A**: **Graceful degradation**. The fire-and-forget pattern wraps AI calls in try-catch:
```javascript
(async () => {
  try {
    await axios.post(PYTHON_SERVER + '/analyze-post', payload);
    // update Question
  } catch (err) {
    console.error(err);
    // silently swallow — post exists but without AI data
  }
})();
```
Posts will still be created, displayed, and interactive — they just won't have sentiment badges, misinformation flags, or cluster assignments.

---

### Q24: How does the system handle race conditions in voting?

**A**: Three mechanisms:
1. **Unique indexes** on Vote/QuestionVote prevent double-voting at the database level
2. **`$inc` atomic operator** ensures concurrent votes don't cause lost updates on the count
3. **Optimistic locking**: The controller checks existing vote state before modifying

---

### Q25: What are the caching trade-offs?

**A**: The Redis cache has a 60-second TTL and is invalidated on every write.

| Pro | Con |
|---|---|
| Feed loads in <50ms on cache hit | Stale data for up to 60 seconds |
| Reduces MongoDB load | Per-user keys mean higher memory usage |
| Simple invalidation with pattern delete | Aggressive invalidation may cause "thundering herd" |

**Thundering herd**: If cache is invalidated and 100 users refresh simultaneously, all 100 hit MongoDB. Solution: mutex/lock on cache miss (not implemented here).

## Section F: Advanced & Scalability

---

### Q26: How would you scale this to 1 million users?

**A**:
1. **Database**: Add MongoDB read replicas; shard by city
2. **Cache**: Move from single Redis to Redis Cluster; add user-level caching
3. **AI**: Run multiple Python worker instances behind a load balancer; use queue (RabbitMQ/SQS) instead of fire-and-forget HTTP
4. **Search**: Replace regex search with Elasticsearch or MongoDB Atlas Search
5. **Feed**: Pre-compute hot feeds; implement fan-out-on-write for followed topics
6. **CDN**: Already using Cloudinary for images — add CDN for API responses

---

### Q27: What would you change about the clustering algorithm for production?

**A**:
1. **Use a vector database** (Pinecone, Weaviate) instead of loading all recent embeddings into memory
2. **Replace brute-force cosine similarity** with Approximate Nearest Neighbors (ANN) — reduces O(n) to O(log n)
3. **Add cluster merging** — two clusters that grow similar should merge
4. **Geo-aware clustering** — same issue in different cities shouldn't cluster together
5. **Decay function** — weight recent posts higher than older ones

---

### Q28: What is Reciprocal Rank Fusion (RRF) and how does it apply here?

**A**: RRF is a method to merge two ranked lists. If document D appears at rank `r₁` in vector results and rank `r₂` in BM25 results:

```
RRF_score(D) = 1/(k + r₁) + 1/(k + r₂)
```

where `k` is a constant (typically 60). MongoDB Atlas uses this internally when you have multiple `should` clauses in a `$search` compound query. It produces superior results because a document that ranks highly in BOTH systems gets a higher combined score than one that only ranks highly in one.

---

### Q29: How does the CivicConnect ↔ UrbanConnect bridge create a flywheel effect?

**A**: 
```
CivicConnect report → syndicated to UrbanConnect → community discusses + votes
                                                        ↓
                                          Upvotes proxied back to CivicConnect
                                                        ↓
                                          Report gains urgency/visibility
                                                        ↓
                                          Authorities more likely to act
                                                        ↓
                                          Resolution → status synced to UrbanConnect
                                                        ↓
                                          Community sees progress → more engagement
```

This creates a **positive feedback loop**: more engagement → more visibility → faster resolution → more trust → more engagement.

### Q30: What are the security vulnerabilities in this implementation?

**A**: (Critical for interviews — shows you think about security)

1. **No server-side auth validation**: Email is passed as a query param — anyone can impersonate another user
2. **Regex injection**: Search queries are passed directly to `new RegExp()` — malicious regex could cause ReDoS
3. **No rate limiting**: Endpoints can be hammered with requests
4. **No input sanitization**: Post content could contain XSS payloads (though React Native mitigates this)
5. **Fire-and-forget has no retry**: Failed AI analyses are silently lost

**Fixes you'd propose**: JWT middleware, sanitize regex input, express-rate-limit, input validation (Joi/Zod), message queue with retry for AI tasks.

## Section G: Quick-Fire Conceptual Questions

---

### Q31: What is `.lean()` and when should you use it?
**A**: Returns plain JavaScript objects instead of Mongoose documents. Use for read-only operations. ~5x faster. Don't use if you need `.save()`, virtuals, or middleware hooks.

---

### Q32: What is `$inc` and why is it important?
**A**: MongoDB atomic increment operator. `$inc: { votes: 1 }` increments without reading first, preventing race conditions in concurrent environments.

---

### Q33: What is cursor-based pagination's biggest limitation?
**A**: You can't jump to "page 50" — you must traverse page by page. This is fine for feeds but not for admin dashboards.

---

### Q34: What is the difference between `populate()` and `$lookup`?
**A**: `populate()` is Mongoose sugar — it runs a separate query per reference. `$lookup` is a MongoDB aggregation stage that runs a server-side join, more efficient for complex queries.

---

### Q35: What design pattern does `civicSyndication.js` follow?
**A**: **Adapter/Bridge pattern** — it adapts CivicConnect's report format into UrbanConnect's Question format, bridging two subsystems with different data structures.

---

### Q36: Why use `Promise.all()` in the City Pulse controller?
**A**: The 4 scraping sources (Tavily, Twitter, Reddit, News) are independent. Running them in parallel reduces total time from `T₁+T₂+T₃+T₄` to `max(T₁,T₂,T₃,T₄)`.

---

### Q37: What is the sparse index and when would you use one?
**A**: A sparse index only includes documents that have the indexed field. Use when the field is optional and unique — without sparse, all `null` values conflict. Example: `auth0Id` on the User model.
